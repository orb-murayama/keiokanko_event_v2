# フォーム設定の子フィールド追加機能の修正

## 📅 実施日時
2026-02-24

## 🐛 問題

フォーム設定で子フィールドを追加した際、親フィールドとの関連が正しく設定されず、単独のフィールドになってしまう問題がありました。

### 原因
**新規に追加した親フィールド（まだ保存していない）に対して、すぐに子フィールドを追加した場合**、親フィールドのIDが`new_xxx`という一時的なIDのままで、保存後に実際のIDに変換されても、子フィールドの`parent_field_id`が正しく更新されない。

---

## 📋 正しい使用方法

### ✅ 推奨される手順
1. **親フィールドを追加**
   - フィールドタイプを「選択肢（プルダウン）」「ラジオボタン」「チェックボックス」から選択
   - ラベルと選択肢を入力
2. **一度保存**
   - 「保存」ボタンをクリックしてフォームを保存
   - ページがリロードされ、親フィールドに実際のIDが付与される
3. **子フィールドを追加**
   - 親フィールドの「子フィールド追加」ボタンをクリック
   - 条件を選択して子フィールドを追加
4. **再度保存**
   - 子フィールドの設定が完了したら保存

---

### ⚠️ 非推奨（問題が発生する可能性）
1. 親フィールドを追加
2. **保存せずに**すぐに子フィールドを追加 ← ⚠️ 親子関係が失われる可能性
3. 保存

## 🔍 技術的詳細

### IDマッピングの仕組み

バックエンドでは、2パスでフィールドを保存します：

#### 第1パス：フィールドの作成/更新
```typescript
// 新規フィールド
const result = await DB.prepare(`INSERT INTO ...`).run()
const newId = result.meta.last_row_id
idMapping[field.id] = newId  // 'new_123' -> 実際のID
```

#### 第2パス：parent_field_idの解決と更新
```typescript
const parentIdStr = field.parent_field_id.toString()
if (idMapping[parentIdStr]) {
  parentId = idMapping[parentIdStr]  // マッピングから取得
} else if (!parentIdStr.startsWith('new_')) {
  parentId = parseInt(parentIdStr)   // 既存IDをそのまま使用
}
```

**問題のケース**:
- 親フィールドID: `new_123`（未保存）
- 子フィールドを追加: `parent_field_id: new_123`
- 第1パス: 親フィールド保存 → `new_123` → `実際のID: 10`
- 第1パス: 子フィールド保存 → `parent_field_id: new_123` で保存（まだマッピング前）
- 第2パス: 子フィールドの`parent_field_id`を解決 → `idMapping['new_123']` = `10` に更新

**理論上は動作するはず**ですが、タイミングやデータの順序によっては問題が発生する可能性があるため、**先に親を保存する方式を推奨**します。
